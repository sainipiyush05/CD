Phase · 01 🔤

Lexical Analysis

Tokenizes raw source code into a stream of meaningful tokens — keywords, identifiers, operators and literals.

→ Phase · 02 🌳

Syntax Analysis

Builds a parse tree from the token stream, verifying grammatical structure against the language grammar.

→ Phase · 03 🔍

Semantic Analysis

Checks type compatibility, scope, and meaning. Ensures the program is logically consistent beyond syntax.

→ Phase · 04 ⚙️

Simplifies and improves the intermediate code to reduce redundancy and improve runtime performance.

→ Phase · 06 🖥️

Translates optimized IR into actual x86 assembly instructions ready for execution on hardware.

Phase 1 — Lexical Analysis

The Lexer (or Scanner) reads the raw source characters and groups them into a sequence of tokens. Each token has a type and a value.

source_program.c
#include <stdio.h>
int main() {
   int choice = 2;
   switch(choice) {
      case 1: printf("Option 1 selected\n"); break;
      case 2: printf("Option 2 selected\n"); break;
      case 3: printf("Option 3 selected\n"); break;
      default: printf("Invalid choice\n");
   }
   return 0;
}

Phase 4 — Intermediate Code

Three-Address Code (TAC) is generated — a linear, machine-independent representation using temporary variables and labels.

intermediate_code_TAC.ir
// Three-Address Code — Switch(choice)

t1 = choice == 1
if t1 goto L1
t2 = choice == 2
if t2 goto L2
t3 = choice == 3
if t3 goto L3
goto L4

L1: print "Option 1 selected"
    goto END
L2: print "Option 2 selected"
    goto END
L3: print "Option 3 selected"
    goto END
L4: print "Invalid choice"
END:

Phase 5 — Code Optimization

The Optimizer eliminates redundant temporaries and simplifies branch conditions, reducing instruction count without changing behavior.

before_optimization.ir
// Redundant temporaries
t1 = choice == 1
if t1 goto L1
t2 = choice == 2
if t2 goto L2
t3 = choice == 3
if t3 goto L3
goto L4
after_optimization.ir ⚡
// Temporaries eliminated
if(choice==1) goto L1
if(choice==2) goto L2
if(choice==3) goto L3
goto L4

// 3 fewer instructions
// Same logic, less memory

Phase 6 — Target Code Generation

The final phase maps optimized IR to actual x86 assembly instructions. Registers are allocated and jump instructions are emitted.

target_code.asm (x86)
; Load choice into register R1
MOV R1, choice

; Compare and jump
CMP R1, 1
JE L1
CMP R1, 2
JE L2
CMP R1, 3
JE L3
JMP L4

L1: PRINT "Option 1 selected" ; JMP END
L2: PRINT "Option 2 selected" ; JMP END
L3: PRINT "Option 3 selected" ; JMP END
L4: PRINT "Invalid choice"
